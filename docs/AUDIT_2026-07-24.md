# Audit technique & architecture — GPUbnb (2026-07-24)

Ce document remplace l'audit obsolète `AUDIT_REPORT.md` (daté du 2026-07-23),
qui décrivait l'agent et la vérification des heartbeats comme « inexistants »
alors qu'ils sont désormais implémentés et testés. Il reflète l'état réel du
dépôt vérifié en exécutant la build, les tests et la chaîne agent complète.

| Composant | Commande | Résultat |

Environnement local : Node 22, Python 3.12 (CI) / 3.10 (compatible),
PostgreSQL 16 + Redis 7 via `infra/docker-compose.yml`.

## 2. Architecture réelle

```
apps/web/     Frontend statique (HTML/CSS/JS vanilla), déployé sur Netlify
apps/api/     API Fastify 5 + Prisma 6 + PostgreSQL + Redis (source de vérité)
agent/        Agent Python (CLI) : identité Ed25519, liaison, heartbeats signés,
              détection GPU NVIDIA/AMD/Intel, jobs, + simulateur
programs/     Contrat d'escrow Solana (Anchor, Rust) — non déployé (devnet)
docs/         Documentation
infra/        docker-compose (Postgres + Redis) pour le dev local
```

Fichiers dupliqués à la racine (`server.ts`, `auth.ts`, `schema.prisma`,
`app.js`, `settlement.ts`, `lib.rs`, `index.html`, …) : ce sont des copies
héritées du prototypage initial. Ils **ne sont pas** utilisés par la CI ni par
les déploiements (qui ciblent `apps/api`, `apps/web`, `agent`, `programs`). Ils
n'ont pas été supprimés dans cette itération pour ne rien casser ; leur
nettoyage est proposé au §5.

## 3. Corrections apportées dans cette itération

1. **Vulnérabilité HIGH bloquant la CI** — `find-my-way` (dépendance transitive
   de Fastify, `GHSA-c96f-x56v-gq3h`, DDoS HTTP/2) faisait échouer
   `npm audit --audit-level=high`. Corrigée via `npm audit fix` (mise à jour non
   cassante, lockfile mis à jour). Il reste 3 vulnérabilités *moderate* liées à
   `@solana/web3.js`/`jayson`/`uuid` qui exigeraient une version cassante — non
   corrigées ici, elles ne bloquent pas la CI.
2. **Simulateur d'agent GPU** (`agent/gpubnb_agent/simulator.py`) — demandé au
   §15 du cahier des charges. Permet de tester le site sans vrai GPU. Voir §4.
3. **`.gitignore`** — ignore désormais `*.egg-info/` et `apps/api/data/`
   (artefacts générés).

## 4. Simulateur d'agent GPU

`gpubnb-agent simulate` crée des machines GPU factices, chacune avec sa propre
clé Ed25519, qui parlent le protocole signé réel (liaison → challenge →
heartbeat). La chaîne de sécurité serveur est donc réellement exercée.

- **Reproductible** : toute l'aléatoire passe par un `random.Random(seed)`.
- **Catalogue** : RTX 4090/3090/3080, A100, H100, L4, RX 7900 XTX, Arc A770.
- **Scénarios** : `steady`, `idle`, `spike`, `overheat`, `failure`, `flapping`,
  `mixed` (répartit les scénarios sur la flotte).
- **Métriques valides** : utilisation, VRAM utilisée/libre, température,
  puissance, ventilateur, évoluant dans le temps avec un modèle thermique
  inertiel. Les bornes respectent la validation serveur
  (`memoryUsed ≤ vram`, `util ≤ 10` quand le probe CUDA échoue, etc.).
- **Modes** : hors-ligne (JSON, sans réseau) et live (contre une API réelle).

Tests : `agent/tests/test_simulator.py` (déterminisme, bornes, transitions de
panne/déconnexion, vérification cryptographique de la signature du heartbeat
contre la chaîne canonique attendue par le serveur).

## 5. Recommandations priorisées (non encore faites)

Priorité haute
- Nettoyer les fichiers dupliqués à la racine du dépôt (base propre). À faire
  prudemment, après confirmation qu'aucun déploiement ne les référence.
- Détection multi-GPU par machine : aujourd'hui le modèle `Machine` porte un
  seul GPU. Introduire un modèle `Gpu` lié à `Machine` pour les hôtes multi-GPU.
- Métriques temps réel côté tableau de bord (WebSocket/SSE), aujourd'hui absent.

Priorité moyenne
- Révocation serveur d'un agent + déconnexion à distance depuis le tableau de
  bord propriétaire (le champ `keyRevokedAt` existe déjà, l'UI/route manquent).
- Filtres marketplace (modèle, VRAM, prix, région) côté frontend.
- Notifications e-mail (l'architecture d'alertes est à préparer).

Bloqué sur décisions/secrets utilisateur
- Déploiement du contrat d'escrow Solana (nécessite une keypair de déploiement
  et des fonds devnet, puis le Program ID en configuration).
- Exécution réelle des charges GPU en conteneur isolé (Docker + NVIDIA Container
  Toolkit) : volontairement désactivée tant que l'isolation et la facturation ne
  sont pas validées, conformément au §13 du cahier des charges.

## 6. Sécurité — état

Déjà en place et vérifié : signatures Ed25519 sur toutes les requêtes agent,
challenge anti-rejeu + compteur monotone, cohérence des télémetries, quarantaine
après échecs répétés, rate limiting, sessions Redis avec TTL/idle, cookies
`httpOnly`/`SameSite=strict`, en-têtes Helmet + CSP, vérification d'origine,
garde-fous mainnet (audit obligatoire), clé privée de l'agent jamais transmise.
